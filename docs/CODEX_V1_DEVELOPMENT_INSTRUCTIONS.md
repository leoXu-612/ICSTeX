# ICSTeX 下一代正式版：Codex 开发任务说明

编写日期：2026-09-10

本任务的目标是交付一代可独立使用、数据可靠、工作流完整的本地科研写作产品。
核心主线是：建立项目 → 组织材料 → 写作排版 → 检查修订 → 导出与恢复。
旗舰组合是统一项目工作台、可追溯的素材与引用、提交前检查中心。

本文是交给后续 Codex 会话的执行说明，不代表功能已经实现或已经通过验收。
仅当用户明确要求“按本说明执行开发”时，才激活下述本地开发范围。
当前会话仅编写本说明，不启动产品开发，也不切换现有 Beta 发布任务。

## 1. 执行范围与授权边界

### 1.1 本地开发范围

本说明激活后，可以按阶段修改项目源码、测试和相关开发文档，创建合成测试项目，
运行本地测试与隔离的源码版 GUI 验证。应真正实现可用功能，不能仅交付规划、
静态界面、占位按钮或依赖假数据的演示。

“V1”是第一代成熟正式产品的工作代号，不是把实际版本号改为 1.0.0 的指令。
实际版本以 app/__init__.py 为源；版本选择、发布序号和渠道变更另行确认。

当前任务的可交付终点是“已验证的源码候选及发布准备清单”。正式发布还需要
独立的维护者授权、平台环境和发布验收，不能将二者混称为完成。

### 1.2 不包含的行为

- 不自动提交、推送、合并、打标签、创建 Release、上传资产或部署网站/appcast。
- 不触发 GitHub Actions，不更改仓库安全设置、账号配置或系统代理。
- 不执行应用打包、安装版替换、Developer ID 签名、公证或真实升级安装；
  这些操作须进入单独获批的发布任务。
- 不读取、导出或新建私钥与令牌，不把旧会话中的凭据授权视为本任务授权。
- 不修改真实学生论文、IA、EE、报告、数据或参考文献；默认只用合成材料。
- 不移动用户现有工程、不改变 iCloud 设置、不主动下载用户其他云端文件。
- 不自动创建新会话、启动子代理、建立定时任务或常驻后台服务。

发布相关源码与测试可在后述边界内准备；涉及安装器生命周期、辅助进程、
多实例策略或既有信任模型的改变，先提出有界方案并获得明确决定。
“继续”“完成 V1”不能用来跳过这些边界。

### 1.3 与现有任务的关系

先读 FORCODEX.md，识别旧任务的占用范围和未关闭风险。用户明确启动本说明后，
本会话以本文的本地开发范围为准，不自动继承 FORCODEX.md 中旧 Beta 发布授权。

不得直接覆盖仍被其他会话使用的 FORCODEX.md。默认保留它，在
docs/V1_IMPLEMENTATION_PLAN.md 记录本会话的当前有界 slice 与下一步。

handoff 的完整入口与未完成门槛。本文不改变 AGENTS.md 的安全和工程约束。

## 2. 开始前必须完成的检查

权威路径为用户选择的 ICSTeX Git 仓库根目录；以下路径均相对此根目录。
在当前工作区以这条命令核实实际路径，不依赖其他维护者机器上的固定目录：

    git rev-parse --show-toplevel

先运行：

    pwd -P
    git rev-parse --show-toplevel
    git branch --show-current
    git status --short
    git diff --stat

确认实际 Git 根与用户选择的工作区一致。若用户明确选择了 Git worktree，验证它
确实属于该仓库，并说明基线来源。不要在 legacy/backup 副本中编辑，不要因 Git
检查失败而初始化新仓库。不能仅从 HEAD 新建 worktree 后声称包含现有未提交功能。
若维护者要求创建开发分支，使用 codex/ 前缀，先明确基线如何保留现有修改。

按顺序完整阅读：

1. AGENTS.md。
2. docs/PROJECT_STATE.md。
3. FORCODEX.md 及其直接关联的未完成 handoff。
4. docs/ROADMAP.md、docs/DECISION_LOG.md。
5. docs/MEMORY_MANAGEMENT.md、SECURITY.md、PROJECT_INDEX.md、README.md。
6. 进入更新/分发设计时，再读 docs/BETA_ACTIVATION_HANDOFF.md、
   docs/update-delivery-design-2026-09-08.md 和 packaging/UPDATES.md。

以上文件名若已调整，通过 PROJECT_INDEX.md 和实际目录定位替代来源，不猜造文件。
Memory 和历史日志用于找原因，当前源码、实际检查和本轮测试用于判断现状。

建立本轮基线清单：分支/提交、未提交和未跟踪文件、解释器与关键依赖、可用平台、
已知测试失败及原生警告。保留原有修改，按文件/hunk 区分本轮变更。不要自动
stash、reset、checkout、清理 dist，或把别人的修改混入“本轮实现”。
如果其他会话正在改同一模块，先完成不重叠工作；无法安全分离时请求协调。

## 3. 产品范围与成功标准

主要用户是需要完成中文或中英混合科研写作的学生，兼顾 LaTeX 初学者与源码用户。
优先支持已有普通 LaTeX 项目和已有 Block 项目；不是另起一种封闭文档格式。

必须覆盖三条代表性工作流：

| 工作流 | 用户任务 | 可观察的完成结果 |
| --- | --- | --- |
| 新用户开始写作 | 检测环境、建立项目、插入图表和引用、首次编译 | 用户知道缺什么、下一步做什么，并得到与源码对应的正式 PDF |
| 长文档持续修订 | 多文件、未保存内容、外部素材变化、章节与引用导航 | 编辑、诊断、字数和 PDF 状态一致，变化能定位且不覆盖用户内容 |
| 提交与恢复 | 检查问题、固定版本、导出、比较和恢复 | 交付文件来源明确，恢复结果可验证，失败不损坏现有项目 |

默认优先用当前可用平台做源码与原生开发验证，不把“在这台机器能运行”当作
跨平台验收。首发平台与最低系统版本属于维护者选择；缺少 Windows 环境时可以
继续平台无关开发，但必须保留 Windows 验收缺口，不能擅自宣布缩减支持范围。

暂不纳入本次首发范围：云端实时协作、账号体系、通用插件市场、完整语言服务器、
任意 LaTeX 的通用 WYSIWYG、PDF 反向编辑、完整电子表格、AI 自动改写正文。
本地审阅批注、复杂数据分析和更广泛 AI 协助先列后续候选，不成为首发依赖。

## 4. 不可破坏的约束

- 中文优先、默认离线；网络动作显式触发，说明发送内容、目标和失败行为。
- 不捆绑完整 TeX distribution；环境检测与引导复用现有 Environment Doctor。
- 沿用 Python/PySide6；纯规则在 app/core，Qt 编排在 app/gui，core 不导入 gui。
- MainWindow 保持兼容门面，采用 focused controller 和小型 seam 渐进演进。
- compile root、source revision、依赖身份、build id 与 PREVIEW/FINAL purpose
  共同约束结果归属；不能用 mtime 或“最近一次结果”替代。
- PREVIEW 和 FINAL 继续路径隔离；正式导出只接受匹配当前输入的成功 FINAL。
- 保存/编译不移动光标或滚动；同文档 PDF 重载保留页码、缩放和视口。
- 失败构建保留的旧 PDF 必须标为 stale；后台结果不能覆盖无关项目或标签页。
- 严格解码、原子替换、项目边界校验和外部冲突保护继续有效。
- 打开项目不等于授权编译；忽略项目 latexmkrc、禁止 shell escape 和现有超时策略不变。
- 文件模型保持只读；变更通过受控操作执行，不增加静默引用重写、隐式删除或越界移动。
- 公式/表格编辑维持隔离草稿、显式提交、revision 校验、一次 Undo 和 Cancel 零修改。
- MCP 仍项目绑定、默认只读，由启动参数授予能力；不能与同项目可编辑 GUI 并行写入。
  不自动扩展 wire contract、权限、传输方式或多写者拓扑。
- 不手工修改生成的 build、dist、应用包或缓存来伪装源码实现。

新增依赖必须有具体必要性，检查许可证、离线行为、启动/内存成本和目标平台打包
影响。引入重型渲染器、改安全边界或改变用户文档权威格式，必须先走独立决策。

## 5. 实施方式与阶段安排

每个 slice 开始前说明：用户任务、修改范围、复用模块、状态归属、失败路径、
验收用例和回退边界。完成一个可运行 slice，再进入依赖它的下一个。
局部设计和测试驱动的小改动可自主推进；不要把每个字段选择都交给用户。

不得为“世代升级”一次性重写全部 GUI、编译器、watcher 或项目存储。
先消除会使当前 slice 丢数据或错误交付的阻塞，再扩展功能。

### M0：核实基线与形成可执行规格

交付 docs/V1_IMPLEMENTATION_PLAN.md，内容包括范围、阶段依赖、验收清单、
当前唯一 active slice、阻塞及下一项安全工作；它不重复保存完整 release matrix。

具体任务：

- 区分已有能力、只有部分链路的能力和真正缺口，避免重复实现公式编辑、
  历史快照、后台字数、来源记录、快速预览或 MCP。
- 检查路线图中旧版本、Candidate 状态与已实现能力的漂移；只在核实后修正。
- 运行必需基线测试，记录已存在的问题。复核已记录的 Qt 对象生命周期异常、
  更新安装互斥与平台验收缺口，不因历史测试通过就标记关闭。
- 为三条工作流建立最小合成项目：单文件、多文件含图表/BibTeX、Block 项目。
  加入中文路径、未保存内容、未知宏、资源缺失和冲突变体。
- 建立性能基线，先确定样本与测量方法，再给出本轮拟采用的目标。

验收：能说明每个首发功能的实现差额、验收方式和授权边界。M0 完成后，
若没有阻塞，应继续 M1 的本地实现，不停留在只写规划。

### M1：提交检查中心的最小纵向切片

先做真实、只读的提交检查，验证跨模块状态是否能可靠汇总。

检查范围：未保存内容、当前 compile root、工具链、正式构建、PDF 新鲜度、
Word Count 统计模式与目标、未解析 citation/reference/label、缺失资源。
复用现有 diagnostics、word_count、pdf_state、依赖分析和 Environment Doctor。

每项结果至少表达：稳定的规则标识、适用范围、状态、原因、证据位置、
下一步操作及结果对应的输入身份。通过/失败/检查中/未知/不适用必须可区分；
警告严重程度不能代替状态，未知不能被计为通过。

界面提供问题定位和用户主动刷新。检查本身不保存、不编译、不联网、不改正文；
“保存”“正式编译”等下一步动作必须复用已有授权和冲突处理流程。
不要设计虚假的综合分数或“保证满足学校/IB 要求”的成功状态。

验收：修改正文、子文件、图片、引擎或当前 root 后，旧检查不会继续冒充当前结果；
后台晚到结果、窗口关闭、取消和检查失败均安全；检查前后学生内容零变更。

架构门槛：只有该纵向功能证明需要更通用的 session seam 时，才按 D010 建立
最小只读接口与回归证据。现有 Block ProjectSession 不代表全应用状态已统一。
不得跳过 Accepted/Proposed 决策的 promotion gate。

### M2：项目工作台、首次使用与渐进式可视编辑

把项目、章节、素材、引用、问题和历史组织为一致的导航；清晰显示活动项目、
编译入口、保存状态以及当前 PDF 类型。保留已有多窗口和源码编辑快捷方式。

首次使用串联项目创建、环境检测、工具安装指引、示例和首次正式导出。
环境缺失时允许打开与编辑，不阻塞启动；安装 TeX 由用户选择，不静默执行。

Project profile 采用本地声明式数据，覆盖已有模板、引擎、目录建议、字数目标和
检查选项。可编辑、可禁用；不接受可执行脚本。没有当前权威来源的课程数值留为
用户配置，不编造默认规则。确需引入课程规则时核对官方来源并记录适用版本。

沿用现有公式、表格、图片和 Block 能力，统一入口、草稿操作与状态提示。
普通 LaTeX 的源码保持权威；Block 项目明确元数据、受管生成区域与用户源码的
归属。切换模式不隐式转换全篇、不覆盖未知宏和手写内容。

验收：键盘可完成核心流程，焦点/IME/Undo 行为一致；现有 UI Scale 档位及小窗口
下关键按钮可访问；原生观察与测试证明保存、导航和 PDF 视口非回归。
新用户可理解下一步，不要求先认识内部模块名。

### M3：素材、引用与来源追踪

复用 BibTeX、显式 DOI/arXiv 导入、SourceRecord、数据源检查和表格三方合并。
优先实现来源列表、内容使用位置、缺失/移动/变化状态与受影响对象的可解释提示。

引用健康检查区分技术错误与建议：重复 key、不可解析字段、缺失引用与未使用条目。
不因未使用而删除文献，不因元数据查询结果不同而覆盖用户整理的条目。
依赖扫描的静态覆盖范围、大小限制和未知宏必须可见，不承诺解释任意 TeX。

首个 slice 只读。需要技术修复时，再做独立的差异预览、用户确认、revision/CAS、
冲突拒绝和可撤销事务；不能顺手开放文件重命名后的批量引用重写。
来源信息表示文件关系和版本，不证明实验数据真实或学术结论正确。

验收：原始数据变化能定位受影响表格；本地编辑与源变化冲突不静默丢失；
未联网仍可检查本地引用，取消查询/修复不改用户文件。

### M4：项目级快照、草稿恢复与安全迁移

先审计并复用现有 history、MCP preimage 和 Block 存储，不直接假定单文件历史
已经构成项目一致性备份。项目级检查点覆盖选定的 tex、bib、素材和必要元数据，
记录格式版本、项目相对路径与内容摘要；未保存草稿与正式磁盘文件分开表示。
已保存文件按原始字节保留编码和换行；不能用解码再统一写成 UTF-8 冒充原样备份。

先实现“恢复为新目录”的可验证流程，再评估原地恢复。任何恢复不自动覆盖当前
项目；取消、摘要不符、缺失对象、磁盘空间不足或读取中发生变化均保留原件。
采集过程必须验证一致性，检测不到稳定视图时失败并解释，不能标记为完整快照。

保留策略有界且可解释；不得仅依赖与项目同目录的一份历史宣称独立备份。
项目外备份目标由用户显式选择，不静默增加后台云同步或常驻备份服务。
格式迁移先保留原件，在副本验证后再请求切换；未知的新格式拒绝破坏性写入。

iCloud/同步目录处理限定为本地可用性、读取失败和冲突提示，以及用户主动选择的
复制/迁移。目录可枚举不等于文件已下载；无法判定时显示未知。不得根据文件名
后缀就断言云状态，也不直接更改用户 iCloud 设置。

验收：检查点在新目录恢复后，清单中文件摘要一致；未保存草稿可独立找回；
损坏/中断/冲突用例不会产生看似完整的恢复结果，不损坏原项目。

### M5：固定提交版本与交付包

将 M1 检查和 M4 一致性采集组成显式“准备提交”操作。提交版本同时绑定实际
保存的输入、依赖、profile、字数口径、正式构建和导出对象。

复用 FINAL 链路，防止检查、编译、打包之间的输入变化。仅锁定本应用写入口
不能防住外部修改，必须进行必要的内容一致性复核；冲突时取消或重做。
不依赖 mtime 判断，不为此改写原始 LaTeX 或重新设计 preview shadow 文件体系。

默认仅输出用户选择的正式 PDF；源码包和检查报告分别由用户选择。
源码包先展示纳入清单，显式声明未能解析的依赖；排除私钥、令牌、日志、
Git 内部目录、虚拟环境、缓存、个人历史及未经选择的材料，不上传任何内容。
报告记录相对路径、版本/工具链身份、输入和产物摘要、检查时间及未确认项，
不泄露本机绝对用户路径，不把“有哈希”当作所有内容或学术规则已验证。

交付包生成使用独立暂存与最终发布步骤，失败不覆盖之前的成功交付。
普通 tex 项目脱离 ICSTeX 仍能使用；环境/字体等外部依赖说明清楚。
相同源码跨环境编译不必产生字节相同 PDF，不能承诺未验证的完全可复现排版。

验收：合成项目完成从创建到提交包、重新打开及版本恢复的全流程；
过期/预览 PDF 永不成为正式交付；任何输入在过程中改变都能阻止混版导出。

### M6：稳定性、性能与跨平台质量收口

完成全部本地可执行验收，修复本轮引入的回归，并复核 M0 的相关已知缺陷。
全套测试通过不是原生生命周期、中文输入法、辅助功能或真实安装通过的替代品。

测量连续输入、面板刷新、依赖扫描、Word Count、冷/暖预览与 FINAL、可见 PDF
刷新、内存和关闭取消行为。记录机器、工具链、数据规模、冷暖条件、采样次数
和测量边界；资源扫描/统计不在键入主路径反复全量运行，后台队列与缓存保持有界。
目标依据基线和用户可感知等待制定，不能用合成样本承诺所有项目性能。

按实际支持声明验证 macOS/Windows 的路径、字体、IME、剪贴板、缩放、文件锁
及本地 LaTeX 引擎。没有匹配 Windows 环境时列未验收，不用 macOS 测试替代。
可准备测试说明与可本地运行脚本，但不擅自启用 CI、购买设备或安装系统级依赖。

真人可用性测试由维护者安排。代理使用合成数据的流程验证不能冒充真实学生反馈；
记录任务完成情况、需要帮助的步骤和实际观察，不虚构参与人数或成功率。

验收：本地可测矩阵有完整结果和证据；其余项目明确归为待平台/真人验收。
只有全部首发范围验收完成，才能建议维护者进入 release candidate 阶段。

### M7：发布门槛与维护者交接

本阶段默认只交付发布准备清单，不执行发布。复核现有 Beta handoff，保留
安装全生命周期互斥、晚启动实例、强制中断、签名和实际分发等未关闭门槛。
GUI 进程扫描不是安装锁，不因“未观察到损坏”就降低验收要求。

如后续获得独立发布授权，按平台完成版本化构建、源码/制品一致性检查、签名、
必要的公证、干净环境安装、无系统 Python 启动、首次 source-to-PDF、真实升级
与失败恢复。Windows 在 Windows-local 路径、匹配架构环境构建和验收。
是否支持其他架构、选择什么正式版本、如何发布，由维护者确认。

沿用现有 Sparkle/WinSparkle 与固定信任配置；新增 helper、修改固定 SDK、
变更多实例策略须先批准具体设计。不能把维护者保存旧 bundle 的手工恢复描述为
自动回滚，不能把静态网站 JSON 当作受信更新 feed。

发布准备报告必须分别标明：源码完成、平台验收、制品生成、签名/公证、
安装/升级验证、线上分发、真实用户验收。未执行的环节保持未完成。

## 6. 最小验收矩阵

下表是必须覆盖的场景，不限定具体测试文件名；先查已有用例再补充。

| ID | 场景 | 不可接受的结果 |
| --- | --- | --- |
| A01 | 默认离线打开项目、启动检查、缺少 TeX | 自动联网/编译，或无法启动编辑 |
| A02 | root/child、多标签、多窗口、共享依赖 | 将后台结果显示到错误项目 |
| A03 | 连续输入、外部变化、晚到回调 | 旧字数/检查/PDF 冒充当前结果 |
| A04 | 编译失败、取消、停止后晚启动 | 错误覆盖有效产物，或取消后仍启动旧任务 |
| A05 | PREVIEW、FINAL、SyncTeX 与导出 | 预览/过期 PDF 被正式导出或错误定位 |
| A06 | 公式/表格确认、取消、Undo、未知宏 | 隐式正文修改、零值丢失或模式切换覆盖 |
| A07 | 源码与磁盘冲突、来源数据三方变化 | 自动保存/同步丢失任意一方内容 |

## 7. 测试与证据要求

每个逻辑/GUI slice 先运行对应 focused tests；在报告任何源码或 agent-instruction
变更完成前，必须运行仓库要求的完整检查：

    python3 -m compileall -q app tests packaging/install_build_dependencies.py
    QT_QPA_PLATFORM=offscreen python3 -m unittest discover -s tests
    git diff --check

进入独立获批的打包/分发任务前还必须运行：

    bash packaging/preflight.sh

纯规则测试放入对应 core test；GUI 回归复用或扩展 tests/test_gui_editor.py、
tests/test_pdf_panel.py、tests/test_ui_visual.py 及相关模块。新增功能测试名称
依据实际模块确定，不为满足文档命名而复制一套测试体系。

GUI 变化必须检查真实源码版窗口和实际输出，使用隔离配置、临时项目和合成数据，
不替换 /Applications 中的应用，不让验证写入学生项目。原生警告、stderr 异常、
崩溃报告和未执行的辅助功能检查分别记录；不能用 offscreen 截图证明原生稳定。

测试未结束、超时、跳过或环境缺失，不得报告通过。已有失败与本轮引入的问题
分开，允许有界重跑验证偶发项，但不得删除/弱化断言使其变绿。
如果测试时共享源码又改变，重新核对变化范围并重跑受影响验收。

证据应包含命令、退出状态、环境、样本和对应源码身份；产品级结果还需可见 UI、
输出文件或恢复后的内容核验。测试数量不能作为“正式版就绪”的单一指标。

## 8. 文档与完成状态

保持职责分离：

- 本文件：执行总纲和授权边界，不累积阶段完成叙事。
- docs/V1_IMPLEMENTATION_PLAN.md：阶段依赖、验收清单、当前 slice 和下一步。
- docs/PROJECT_STATE.md：仅更新已经验证的当前能力、风险及实际 release matrix。
- docs/ROADMAP.md：未来方向与优先级；不要把尚未验收的能力移到 Delivered。
- docs/DECISION_LOG.md：必要的长期决策；保留旧决策，用新条目说明取代关系。
- PROJECT_LOG.md：每个已验证结果追加一次；精确测试数量与历史证据按既有规则记录。
- README.md/用户指南：只描述用户实际可用的流程，区分源码与公开安装制品。

不要为了任务整齐而批量改写历史、架构规则、其他 agent brief 或全局 Memory。
清理过时事实必须有当前证据，文档更新不得伪造发布状态。

每个阶段收尾用中文报告：完成的用户能力、修改文件、测试及原生证据、
未解决问题、下一 slice；提供建议提交信息，但本任务不自动提交。
有跨会话恢复需要时，留下准确入口、当前未提交状态和下一条可执行动作，
后续会话先核验再继续，不从 M0 重新实现已经完成的功能。

## 9. 停止与交接条件

以下情况暂停相关动作并给出一个明确问题：无法安全区分共享修改、需要改变
Accepted 安全/架构边界、真实学生数据授权不足、需要账号/费用/签名/部署，
或必须选择会显著改变产品范围的平台/格式策略。仍可完成独立且已授权的工作。

不要因为任务规模大或需要多个 slice 就停止；也不要因为时间或上下文有限
把未完成内容标记为完成。到达人工发布门槛时，交付可检查的源码与证据后暂停。

本地开发任务完成须同时满足：M1–M6 范围实现、适用验收通过、本轮无未关闭的
数据损坏/错误导出/权限回归、文档反映真实状态，以及所有外部验收缺口明确列出。
缺少平台或真人验收时，只能报告“本地源码阶段完成，正式发布仍待验收”。

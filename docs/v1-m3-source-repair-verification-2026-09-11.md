# V1 M3: explicit linked-source repair

Date: 2026-09-11 (Asia/Taipei). Local source feature; not a release or complete V1 acceptance.

## Actual workflow

Block **来源 → 比较并合并来源…** now performs a real source-to-model operation.
It requires an explicitly selected project-local original CSV/XLSX whose exact bytes
match SourceRecord's recorded SHA-256. Current Local is never substituted for a
missing Base. The user declares the import options for each linked table, reviews
the actual source captures and Local including pending table drafts, selects each
column mapping plus a unique row key, and confirms an independent merge candidate.
Every linked object must be a supported table and every linked table must be
reviewed before the final transaction can advance the shared source digest.

CSV decoding is strict and explicitly selected. Its text is initially retained
without stripping or type inference; the key-based projection uses the chosen
target column's numeric/date/boolean type for conversion. Text identifiers retain
spaces and leading zeros. Column mappings must account for every source and target
column exactly once. Empty/duplicate/unsupported keys refuse mapping. Actual keys,
not imported row numbers, determine target row identity; reordered rows remain
visible. Target formatting/notes are local policy, not recovered source metadata.
Different structures can require an explicit whole-table choice. Whole-table
replacement uses separate IDs and a final raw-content preview, so coincidentally
equal importer IDs do not silently attach old per-cell attributes to unrelated data.

Each per-table dialog returns only a detached candidate. A separate final dialog
shows complete before/after Block content, including unmodeled fields, before
confirming one operation. Source captures are rehashed in a bounded worker and
their path identity is rechecked after the queued callback; exact source-record,
target/revision, associated-draft and project ownership are checked before applying.
The existing guarded writer's current metadata/generated bytes are checked read-only
before model application and are checked again by normal persistence.

One global Undo restores all affected table content and the previous source record.
Consumed table drafts return as unapplied drafts rebased onto the restored model;
newer/reentrant input is not erased. Existing raw-content projection preserves
unchanged unknown fields. Confirmed application resumes the existing save/preview
policy without granting new compile authority. No original CSV/XLSX is rewritten.
Cancel, missing baseline, unsupported linked object, incomplete mapping, source
change, target/draft conflict and closed session return without applying a command.

This is content-checked observation plus the existing guarded writer, not an OS CAS
against arbitrary uncooperative external writers. Changes after accepted observation
are a new source version; a later disk-save conflict preserves both memory and disk.
SourceRecord's schema is unchanged. No persistent baseline-byte store, automatic
backup or import-option schema was introduced. The original/current source versions
must be retained separately; another repair can require selecting them again.
M4 project checkpoints and recovery remain necessary independent work.

## Bounded input and newly reproduced XLSX defects

Source capture is project-local, link-safe, cancellable between chunks and limited
to 16 MiB per file (Base and Remote are separate captures). Parsing uses captured
bytes only. A repair covers 1–20 linked tables and at most 100,000 aggregate cells;
the existing editor's row/column limits also apply. Each JSON preview is capped at
262,144 characters and incomplete previews cannot be confirmed. This means large
otherwise-valid tables can require a more scalable comparison UI; it is not a claim
that all 100,000-cell projects are currently usable through this dialog. Spreadsheet
parsing is not interruptible inside every third-party parser call and has no hard
OS I/O deadline. The worker owns no widget and has no pending queue. A cancellation
stress test reproduced overlapping retries while an old parser was still running;
`/tmp/icstex-v1-m3-source-repair-worker-red-r1.log`. A session-owned active-read token
now refuses a second read until the prior work actually finishes, even after its
modal has been cancelled. Cancellation returns promptly and never applies late work.

Two adversarial synthetic tests reproduced real adapter defects before the fix:
an XLSX `<dimension ref="A1">` hid later actual body rows, and a formula with no
cached result became an accepted empty cell. Import now inspects actual coordinates,
resets the reader's dimension hint, applies observed/selected bounds and refuses
uncached formula cells. ZIP duplicate entries are refused. Formula execution stays
disabled; existing cached values are not proof that the workbook was recalculated.
The old formula test was strengthened from accepting an empty cell to requiring
refusal, not weakened to permit evaluation. The first new GUI fixture put an opaque
field at an unsupported content-root location and failed its save guard; the fixture
now uses the schema-supported opaque header/cell locations. No format was relaxed.
